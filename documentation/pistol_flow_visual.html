  • Per-serial build record archived
  • FPY / scrap / cycle analytics update

3 · Inside one station visit — Op 30 · Barrel Fit

Every line an operator touches, tagged by which system it belongs to.

What the operator does

  • MES Scans badge → operator session opens at Station 3
  • MES Scans box QR → unit identified, “right station” confirmed, timer starts
  • MES Works through steps: fit breech face → lap lugs → check lockup (photos + tolerances on screen)
  • MES Enters hood clearance measurement — in-tolerance turns green
  • MES One lug out of spec → taps Fail → lead badge → “rework in place”, cause coded
  • MES Re-cuts, re-measures, passes; taps Finish Operation
  • MES→JB2 Time-ticket detail posted: 47 min, 1 piece finished, reason code logged
  • MES→JB2 Routing step 30 patched: actual dates + pieces good
  • JB2 Job cost and schedule update — nobody typed anything into JB2

What got recorded (this visit alone)

  • MES 2 scans · location history + queue-vs-work dwell
  • MES 14 substep completions with timestamps + operator ID
  • MES 3 measurements with nominal/tolerance + gauge ID
  • MES 1 failure event: cause, disposition, lead authorization
  • MES Rework time (11 min) separated from first-pass time (36 min)
  • MES 2 photos attached to the serial's build record
  • MES→JB2 1 time ticket + 1 routing update (the only part JB2 can hold)
JB2 receives 2 records; the MES keeps ~20. That 10× granularity is what powers the dashboard below.

Data provenance on every card — from JobBOSS²: model/part, order + line, quantities, due date, routing sequence. from MES: serial, box, live location, operator, step progress, first-pass/rework state, failure codes, dwell timers, transit times.
How to read this page: JB2 defines what to build and in what order (blue). The MES runs the bench: instructions, scans, measurements, rework (red). At each operation close, the MES pays its “tax” back to the ERP (amber) so costing and invoicing never need manual entry. The dashboard is possible only because the red layer exists — none of its live detail is representable in JB2.
